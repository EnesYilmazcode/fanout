Fanout

One endpoint, all your keys. Bring your own credentials, pool them, and call any provider through a single OpenAI-shaped API — with no database anywhere in the stack. This is the interactive demo — the home page hands you your key and one copyable config block.

Drop it into your app

  

    

      Nothing to install. Fanout speaks OpenAI's wire
      format, so the SDK you already use works — point baseURL at Fanout and go.
      Switching providers is editing one string.
    


import OpenAI from 'openai'

const fanout = new OpenAI({
  baseURL: '$ORIGIN/api/v1',
  apiKey: process.env.FANOUT_KEY,
  defaultHeaders: { 'X-Fanout-Connection': process.env.FANOUT_CONNECTIONS },
})

await fanout.chat.completions.create({
  model: 'anthropic/claude-opus-5',   // -> openai/gpt-4o -> groq/llama-3.3-70b-versatile
  messages: [{ role: 'user', content: 'hi' }],
})

    

      Same in Python, the Vercel AI SDK, or raw HTTP — it's two headers and a JSON body:
    


curl $ORIGIN/api/v1/chat/completions \
  -H "Authorization: Bearer $FANOUT_KEY" \
  -H "X-Fanout-Connection: $CONN_A,$CONN_B" \
  -H "Content-Type: application/json" \
  -d '{"model":"anthropic/claude-opus-5",
       "messages":[{"role":"user","content":"hi"}]}'

    

      Comma-separate connections to pool them. Fanout picks one at random and fails over to the
      next when a provider returns 401, 429, or 5xx — so your pool behaves like one key with the
      combined quota. Response headers tell you which one served you and how each attempt went.
    

  


  

    Stateless by construction: keys are HMAC signatures, connections are AES-GCM blobs you hold.
    A demo, not a production service — read the source
    before you trust it with a real credential. Every endpoint and error is written up in
    the docs.
